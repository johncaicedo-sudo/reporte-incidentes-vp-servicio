1. Resumen Ejecutivo

  • Objetivo: Implementar plataforma BPMS (Bizagi Cloud) para centralizar y automatizar flujos de trabajo.
  • Reemplaza: Oracle IPM Stellent, IBM Filenet, Bizagi on-premise, ImagineX-nativo — de 7 plataformas a 3.
  • Beneficios: Tracking 100% de casos, -144 horas/mes manuales, eliminación de 829 casos/mes manuales (outsourcing), ahorro $9M/mes.
  • Inversión: 15 meses, Capex externo $735M, Capex interno $196M.

4. Contenido Estratégico

  • Licenciamiento: Bizagi Cloud Transacciones Ilimitadas, 7.500 prompts, 200 usuarios, Soporte Bronze.
  • BPU: 1 BPU = 10.000 Pasos/mes (un paso = cualquier elemento donde se ejecuta una acción).
  • Fases: Fase 1 (Gattaca + interno), Fase 2 (interno + 1 mes Gattaca), Fase 3 (interno).
  • Opex: $276M/año licencias, $58M soporte, $165M infra 6 meses.

5. Dependencias y Riesgos

🔗 Dependencia Integraciones Core

El flujo no se ejecuta sin respuesta de Sistema Terceros (perfil + CLV), Tronador (pólizas + reserva proceso 70) y Registraduría (validación documento). Si una integración falla, el proceso va a Gestión de Inconsistencias.

🤖 Riesgo IA: Agotamiento de Prompts

7.500 prompts contratados. Cada caso consume mínimo 2 prompts (Refinador + Especializado). Con 829 casos/mes = ~2.487 prompts/mes. Cuota agotada en ~3 meses.

📊 Riesgo BPU: Alto Consumo

Iteraciones complejas (subprocesos de Múltiples Instancias para adjuntos y reservas masivas) detonan alto consumo de BPUs. Evaluación anual podría cambiar modelo de licenciamiento o aumentar costo radicalmente.

    Priorizar desbloqueo de P1: Resolver las definiciones de integraciones pendientes para liberar la cadena de certificaciones. Las 5 APIs bloqueantes (Core X, Lago de Datos, Carpeta Única, IA) son la causa raíz.

El proyecto presenta un retraso estructural causado por cambios en las definiciones de integraciones. Los 3 paquetes están impactados con un efecto cascada que compromete la fecha de despliegue a producción (19/06/26). Se estima un retraso mínimo de 45 días en el escenario más optimista.
